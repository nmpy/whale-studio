# チケット連携（PR2）Preview 動作確認手順

このリポジトリには Playwright / Cypress / Storybook / jsdom / testing-library のいずれも無く、
**ブラウザ自動テスト基盤が存在しない**（`vitest` の `environment` は `node`）。
そのため UI は API・純関数テストでカバーし、画面の確認は本手順の手動確認で行う。

## 0. 前提：DB migration

チケット連携は以下 2 本の migration が適用済みの DB でないと動作しない。

| migration | 内容 |
|---|---|
| `20260801000000_add_ticket_link_models` | ticket_links / ticket_link_drafts / members / sync_logs |
| `20260801000001_add_ticket_link_manual_flow` | draft.step / ticket_type_key / 競合用の部分 UNIQUE |

**未適用の DB では、LIFF の設定取得 API と管理画面の設定保存は 500 になる。**

`CLAUDE.md` の運用では Vercel の `DATABASE_URL` を Production / Preview / Development の
全環境へ同じ値で設定する。したがって **Preview は本番 DB を参照する**。
本番 DB への適用は運用判断が必要なため、本 PR では適用していない。

適用する場合は `CLAUDE.md` の手順に従い、ローカル Terminal から Session Pooler(5432) URL を
一時 export して `npx prisma migrate deploy` を実行する（Vercel の runtime 用 URL は変更しない）。

## 1. 管理画面での準備

1. `/oas/{oaId}/works/{workId}/liff?tab=ticket_link` を開く
2. 上部の帯に「プレイヤーにはまだ公開されません」と不足理由が出ることを確認
3. **チケット連携ページを作成** を押す（既にあれば作成ボタンは出ない＝冪等）
4. 「チケット連携を有効にする」「手動入力を有効にする」をオン
5. **チケット種別を追加** で行を追加し、以下を入力
   - キー `single` / 表示名 `1名チケット` / `1` 人 / 有効
   - キー `pair` / 表示名 `2名グループチケット` / `2` 人 / 有効
   - キー `quad` / 表示名 `4名グループチケット` / `4` 人 / 有効
6. 「登録完了画面の案内文」を入力
7. 報告ボタンを有効にし、**ボタンに表示する文字**（例 `報告する`）と
   **LINEへ送信するメッセージ**（例 `チケット連携が完了しました`）を別々に入力
8. **設定を保存** → 「設定を保存しました」
9. ページの **公開する** を押す
10. 帯が「プレイヤーへの公開準備が完了しています」に変わることを確認

### 管理画面で確認する異常系

- キーを重複させて保存 → 該当行に「キーが重複しています。」
- キーや表示名を空で保存 → 該当行にエラー
- 参加人数を 0 や 21 にして保存 → 該当行にエラー
- 送信メッセージを空にして報告ボタンを有効化 → 保存ボタンが無効
- 有効な種別を 0 件にして保存 → 帯に「チケット種別が設定されていないため…」
- 種別を編集して保存せずタブ/ページを離れる → 未保存警告
- 保存に失敗しても入力内容が消えないこと
- 閲覧のみ権限のユーザーでは入力・保存が disabled であること

## 2. LIFF 実機確認（LINE アプリ）

対象 OA を **友だち追加済み** の LINE アカウントで行う（友だちでないと 403 になる）。

1. LIFF HOME（`/liff/w/{workPublicId}`）を開く
2. 「チケット連携」カードを開く
3. 未登録なら「手動で入力」と「スクリーンショットから登録（準備中・押せない）」が出ること
4. 種別を選択（1 種別だけなら固定表示）、名前、予約番号 `123-456` を入力
5. 「この内容で進む」→ 確認画面で予約番号が**全桁**表示されること
6. 「この内容で進む」→ 人数分のコードネーム入力欄が出ること（1/2/4 名で件数が変わる）
7. 「登録内容を確認する」→ 最終確認に公演・日時・種別・予約番号・コードネームが出ること
8. 「この内容で登録」→ 連打しても二重登録されないこと
9. 完了画面に「チケット連携を受け付けました」と案内文、連携状態「運営確認待ち」が出ること
10. 報告ボタンを押す → LINE トークへ**送信メッセージ**が届くこと（ボタンラベルは届かない）
11. 再度タブを開く → 連携済み表示で予約番号が `123-***` にマスクされること

### LIFF で確認する異常系

- 予約番号を `abc` などにする → 形式エラー
- 入力途中で閉じて開き直す → 「入力途中の情報を再開する」「最初からやり直す」が出る
- 「最初からやり直す」→ 入力が消えて未登録状態に戻る
- 別の LINE アカウントで同じ予約番号を登録 → 「この予約番号は現在確認が必要な状態です。」
  （先行登録者の名前・コードネーム・登録日時が一切出ないこと）
- 同じアカウントで同じ予約番号を再登録 → 既存が返り二重登録されない
- 同じアカウントで**別の**予約番号を登録 → 別レコードとして登録できる
- LIFF 外ブラウザで完了画面を開き報告ボタンを押す →
  「チケット連携は完了しています。LINEへの報告メッセージのみ送信できませんでした。」
  が出て、**登録自体は完了扱いのまま**であること
